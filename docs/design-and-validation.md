## 局部前置研究与选择
- 沿用项目原生 DOM/CSS、localStorage，不迁移框架：现有功能完整，框架重写增加旧数据迁移与部署风险。
- 保留现有 Font Awesome 6.4 图标库（Free 字体 SIL OFL 1.1，代码 MIT，图标 CC BY 4.0）；标准 UI 图标不重造，站点图标仍取网站 favicon。
- 弹层方案比较：现有覆盖层、原生 dialog、第三方 modal。此轮沿用覆盖层并补可访问标签、键盘关闭与焦点管理，降低整套事件修改范围。原生 dialog 的焦点/模态能力可供后续迁移参考。
- 数据方案比较：原有 localStorage、IndexedDB、后端同步。保留 localStorage，针对配额/损坏失败关闭；导入前备份，合法性检测后原子替换。
- 测试：Node 内置 test + jsdom 26.1.0（MIT），仅开发依赖。原项目无测试，不引入产品运行时框架。
- 资料：https://developer.mozilla.org/en-US/docs/Web/HTML/Reference/Elements/dialog 、 https://developer.mozilla.org/en-US/docs/Web/API/Web_Storage_API 、 https://fontawesome.com/license/free 。

## 正常、失败、长期流程
打开 → 读取原数据且不改写 → 分类/搜索 → 新窗口打开网站 → 添加/编辑/删除（确认）→ 拖动调整顺序 → 导出 JSON。
导入 → 解析并验证整批结构/URL → 用户确认替换 → 保存旧数据备份 → 保存新数据 → 更新 UI。解析失败、格式错误或存储失败均保持原收藏。
长期：数据增多可切列表/分类/密度；长文本截断但完整名称可访问；手机侧栏转横向分类；本地数据并非云同步，跨域预览不自动共享旧站点数据，需手动 JSON 导入。
损坏存储保留原始值并显示警告；禁止通过正常编辑静默覆盖。导出原始数据以便恢复。清空/恢复等写操作必须明确。
