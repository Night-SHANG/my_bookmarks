# 导航页视觉统一

目标：在可用的导航功能之上直接美化，不再生成不同风格的图片样板。

保留约束：沿用 `feat/bookmarks-visual-redesign` 的 e2d50c4；不修改 main、不部署。普通桌面最低 4 列 4 行，卡高 94px、空槽留白、分页和首次搜索焦点不变；窄屏按可用空间降级。书签与 localStorage 不迁移、不填入演示数据。

实施方向（本轮设计决定）：延续暖白/低饱和绿，独立侧栏面板、明确的搜索主入口、统一的圆角与细边框、适度卡片层次、统一图标容器、清晰深色模式。不增加壁纸、插画、账号入口、通知、标签等未实现功能。

方案比较：重做框架/交互会扩大风险，继续仅换主题色无法解决层次与图标问题；采用独立 `polish.css` 视觉层和本地 SVG 图标子集，保留已有布局算法与事件。

实现范围：index.html 的文案、控件可访问名称、样式引用；新 polish.css / icons.css；静态构建包含新增资源与许可说明。app.js 不变。

验收：静态资源和图标覆盖测试先失败再修正；原有测试保持，新增 Chromium 验证离线 UI、深色、桌面 4×4、窄屏、管理面板和弹窗。禁止把静态检查当成浏览器视觉验收。当前容器浏览器的 file 与 localhost 访问受管理员策略限制；不绕过，交由既有 GitHub Actions 验证并上传真实截图。
